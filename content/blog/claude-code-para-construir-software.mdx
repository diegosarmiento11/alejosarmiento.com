Uso Claude Code como a un desarrollador nuevo en el equipo: le doy las reglas por escrito, le pido un plan antes de un cambio grande y no doy nada por terminado sin verificarlo. La herramienta rinde tanto como el contexto que encuentra en el repositorio.

## Las reglas viven en el repo

Un archivo `CLAUDE.md` corto, con el stack, los comandos y las reglas que no se negocian. Las decisiones importantes van en documentos aparte, uno por decisión, con el contexto y las alternativas que se descartaron.

Así cada sesión empieza sabiendo lo mismo, y nadie vuelve a discutir lo que ya se decidió.

## Verificar antes de decir "listo"

Un solo comando que corre las revisiones y las pruebas. Si pasa, el cambio puede salir. Si no, no.
